> ## 解释各个选项或者题干
> 
> 核心性质（必须会背）：  
> 对长度为 \(m\) 的有序顺序表，用折半查找取
> \(\text{mid}=\lfloor (low+high)/2 \rfloor\)。
> 则每个内部结点对应的区间长度 \(m\) 被分成
> 
> * 若 \(m=2n+1\)（奇数）：左、右子树元素个数相等（各 \(n\)）。
> * 若 \(m=2n\)（偶数）：右子树的元素个数比左子树多 1（左 \(n-1\)，右 \(n\)）。
> 
> 把“元素个数”换成“该结点左/右子树内部结点个数”，得到结构判据：
> 
> > 在不画外部结点时，任一内部结点都满足  
> > \(|R|=|L|\) 或 \(|R|=|L|+1\)（右边不小于左边，且差至多 1）。  
> > （若用 \(\lceil (low+high)/2 \rceil\)，则变成 \(|L|=|R|\) 或 \(|L|=|R|+1\)。）
> 
> * A：对每个内部结点都能满足“右 = 左 或 右 = 左 + 1”，因此可能是折半判定树。
> * B / C / D：都能在某个内部结点发现“左子树内部结点数 \(>\) 右子树内部结点数”，违反上面的判据，不可能。  
>   例如：
>   * B 的右子树根处，左分支比右分支多；
>   * C 的若干内部结点处出现“左多于右”；
>   * D 的右子树根处也出现“左多于右”。
> 
> ---
> 
> ## 做题思路
> 
> 1. 记住局部大小关系判据（对 \(\lfloor\cdot\rfloor\) 取中点：右 ≥ 左，差 ≤ 1）。
> 2. 对每个选项，自上而下挑一个内部结点，数其左右内部结点个数，看是否满足“右 ≥ 左 且 差 ≤ 1”。
> 3. 仅有 A 全部满足，其他至少有一处违背。

> ## 扩展（408 一体化）
> 
> ### 数据结构（本题所属）
> 
> * 折半查找判定树是唯一的（给定 \(n\)、固定取 \(\lfloor\cdot\rfloor\) 或 \(\lceil\cdot\rceil\) 后就定型），是一棵“几乎完全、略右重”的二叉搜索树。
> * 最坏比较次数（树高）：\(\lfloor \log_2 n \rfloor + 1\)；失败同界。
> * 若画外部结点（失败位置），则外部结点数 = 内部结点数 + 1。
> * 改用 \(\lceil\cdot\rceil\) 时，左 ≥ 右（差 ≤ 1），属等价实现。
> 
> ### 计算机组成原理
> 
> * 树高 ≈ 比较/分支次数：影响分支预测与流水线效率；二分的跳跃访问带来较弱的缓存局部性（Cache/TLB miss 增多）。
> * 外存索引启示：B/B+ 树用高扇出 \(f\) 将“树高”从 \(\log_2 n\) 降为 \(\log_f n\)，减少磁盘 I/O 次数（“树高 ≈ I/O 次数”）。
> 
> ### 操作系统
> 
> * 多级页表：本质是多层索引树；访问层数≈查找步数。TLB 命中可把多层查找折合为 1 次。
> * 文件系统目录/索引：大目录常用 B+ 树（对数高度）或哈希以降低查找代价；顺序目录会退化为线性查找。
> 
> ### 计算机网络
> 
> * 路由最长前缀匹配（LPM）：Trie/压缩 Trie 的“树高 ≈ 查找步数”。也有“对前缀长度做二分”的实现（Binary Search on Prefix Length），比较次数 \(\approx \log_2 W\)（IPv4 \(W=32\)，IPv6 \(W=128\)）。
> * TCAM 并行匹配：硬件一次性比较，等价于把“树高”压到常数，但成本/功耗高。
> 
> > ✅ 一句话记忆：判定树形状判据（不含外部结点）= “右 ≥ 左，差 ≤ 1”（\(\lfloor\cdot\rfloor\) 取中点）；  
> > 反之（\(\lceil\cdot\rceil\)）则“左 ≥ 右，差 ≤ 1”。
