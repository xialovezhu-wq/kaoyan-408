## 主要漏洞

### 1. 快排 vs 归并的"中间序列判别法"

初问时 Q3 用"数有几个元素归位"判快排——不可靠。纠正后立住的判别法：

```
快排 signature：找得到一个支点，左边全部 ≤ 它、右边全部 ≥ 它（它已归位、把数组劈两半）。
归并 signature：整个数组能切成若干段，段长都是 2 的幂、各自内部有序，段间无序。
```

口诀：**快排找"一个左小右大的支点"，归并找"几段等长的有序块"。** 追问"段长 4、4 段、各段内部有序"判为归并（第 2 趟）且"不保证任何元素到最终位置"——一次过，最稳的一块。

### 2. 基数排序 MSD/LSD 不能互换（真错点）

初答把"从最高位开始还是最低位开始"说成"逻辑一样"——错。

```
谁最后排，谁说了算。最高位主导大小 → 必须最后排 → 所以从最低位（LSD）开始。
```

反例（13、21）：LSD 个位→十位，结果 13,21 ✓；MSD 十位→个位，最后个位把十位顺序冲掉，得 21,13 ✗。
补充：稳定性靠"桶 = 先进先出队列（FIFO），收集时按入桶顺序倒出"；空间复杂度 **O(r)**（r 个桶的辅助空间，元素链式不复制）。

### 3. 堆排序的建堆是"向下调整"（真错点）

初答把建堆说成"向上调整"——错。方向对照表（钉死）：

| 操作 | 方向 | 用在哪 |
|---|---|---|
| 向上调整（上浮）| 往根爬 | **插入**新元素（放堆尾后上浮）|
| 向下调整（下沉）| 往叶沉 | **建堆**、**删堆顶**、排序每趟 |

口诀：**建堆和删堆顶都"向下沉"，只有插入才"向上浮"。**

### 4. 外部排序三件套是流水线 + 补虚段的 u=0 边界（最硬的一块，纠正 3 轮）

三件套串成一条线（不是三选一）：

```
置换-选择（造又长又不等长的初始段，平均≈2倍工作区）
 → 最佳归并树（给不等长段排归并次序，哈夫曼思想，让总读写最小）
 → 每趟 k 路归并内部用败者树快速选最小。
```

趟数 S = ⌈log_k m⌉：**m（初始段数）↑趟数↑、k（路数）↑趟数↓。**

补虚段规则（这次的 E09 重灾区）——**两个分支不能只记一半**：

```
设 u = (n−1) mod (k−1)
  u = 0  → 补 0（已满足，别动）
  u ≠ 0  → 补 (k−1) − u
```

踩坑顺序：先把"余数当补段数"（4 路 6 段，余 2 误补 2，正确补 1）；纠正后又在"u=0"时机械套 (k−1)−0=3（4 路 7 段，正确补 0）。最后 4 路 10 段（u=0）主动判"不补"才过。最佳归并树补虚段条件 = r 叉哈夫曼树的 (n−1) mod (r−1)=0，同一个式子。

### 5. 微内核 + 扩充机器 vs VMM（挂了两天的尾巴）

三处全错过：通信机制说成"进程直接通信"（应为**消息传递 IPC、经内核中转**）；微内核慢的原因说成"访问外存"（应为**用户态服务靠消息传递 + 反复用户态↔核心态切换**，服务都在内存里）；VMM 只说"切割内存"（漏了"几台"这条线）。

```
微内核：核心只留 低级IPC/低级进程管理/低级内存管理/中断底层；
        文件系统、设备驱动、网络协议 移到用户态当"服务进程"，靠消息传递经内核中转。
        → 可靠/可扩展高、性能低（慢在消息传递 + 态切换，不在外存）。
扩充机器 vs VMM：扩充机器=把一台机器变"好用"（给应用）；VMM/Hypervisor=把一台变"多台"（给多个 OS）。
```

追问"一台物理机同跑 Windows + Linux 是谁做到的"→ VMM，体现"一台变多台"——答对收口。
