# 2026-05-25 复盘

今天的主线很清楚：数据结构的查找模块集中暴露了三个薄弱层次。

第一层是折半查找的适用条件和判定树形态；第二层是 BST/AVL 中“排序约束”和“平衡约束”的边界；第三层是 B 树、B+ 树的性质、插入、删除和应用场景。今天不是单点失误，而是同一个问题反复出现：看到树形结构时，容易先凭形状或直觉判断，而不是先确认这类树的定义约束。

## 一、折半查找：不是“看起来像数组”就能二分

今天 `DS_2024_002` 暴露的问题是：你知道折半查找必须“有序 + 可随机访问”，但把静态链表误认为数组或顺序表。

正确边界是：

- 折半查找要求有序顺序表。
- “有序”只解决关键字方向问题。
- “顺序表 / 数组”解决 O(1) 定位中点问题。
- 静态链表虽然底层用数组存储结点，但逻辑次序靠游标链接，找第 k 个逻辑结点仍要沿链走。

所以静态链表的本质仍是链式结构，不是可以直接按下标取中点的顺序表。

今天 `DS_2017_002` 进一步暴露了另一个折半查找误区：折半查找判定树不是普通 BST 形态题。普通 BST 只要求左子树小于根、右子树大于根；折半查找判定树还要求每个结点的左右子树规模符合统一取中规则。

这类题以后先问：

```text
是不是数组 / 顺序表？
是不是有序？
判定树每一层是否符合统一取中？
```

不要先看路径是左拐还是右拐。路径可以左、右、左地变化，只要关键字始终落在祖先限制出的区间内。

## 二、BST 与 AVL：排序约束不是路径方向单调，平衡因子不是结点数差

今天有一组 BST/AVL 的复习记录和错题节点，集中暴露了三个边界。

第一个边界：BST 的核心是整棵左子树都小于根、整棵右子树都大于根，不是路径方向必须一直变小或一直变大。

你复习 BST 时已经重新补上：

- 二叉排序树 = 二叉搜索树 = 二叉查找树 = BST。
- 中序遍历递增是 BST 的性质，不是中序遍历天然保证升序。
- 查找路径可以左、右、左地交替，只要每一步仍落在祖先限制的关键字区间中。

第二个边界来自 `DS_2015_003`：中序遍历得到降序序列时，要转成反向排序关系。

普通 BST 是：

```text
左子树 < 根 < 右子树
```

本题语境是中序降序，所以应理解成：

```text
左子树 > 根 > 右子树
```

因此最大元素在最左侧，它一定无左子树；但不能说整棵树不能有左子树。

第三个边界来自 AVL。

`DS_2012_004` 暴露的是：把平衡因子误理解成左右子树结点数差。正确是：

```text
BF = 左子树高度 - 右子树高度
```

所以所有非叶结点 BF=1，翻译出来是左子树高度比右子树高 1。高度为 h 时，左子树高度是 h-1，右子树高度是 h-2，递推才是：

```text
C_h = C_{h-1} + C_{h-2} + 1
```

`DS_2021_001` 暴露的是 AVL 插入调整思路：不能把所有关键字重新排序取中值当根。AVL 插入只做局部维护：

```text
BST 插入
→ 从插入点向上找第一个失衡祖先
→ 判断 LL/RR/LR/RL
→ 只旋转最小不平衡子树
```

这两题合在一起复盘，核心提醒是：

```text
AVL = BST 排序约束 + 高度平衡约束
排序约束看关键字区间
平衡约束看高度差
插入调整看局部旋转
```

## 三、B 树：今天最大的薄弱点

今天 B 树和 B+ 树是最集中的问题。你先做了一次知识点复习，然后又连续入库了 B 树性质、插入、删除、关键字数量和 B+ 树应用相关题。

这说明问题不是某一道题不会，而是 B 树的基本约束还没有形成自动反应。

### 1. m 阶 B 树先写上下限

今天多道题都回到同一条规则：

```text
m 阶 B 树：
最多 m 个孩子
最多 m-1 个关键字
非根结点最少 ceil(m/2) 个孩子
非根结点最少 ceil(m/2)-1 个关键字
根若不是叶结点，至少 2 个孩子、至少 1 个关键字
所有叶结点在同一层
```

`DS_2013_002` 和 `DS_2018_001` 都暴露了最少关键字数下界不熟。求“至少”时，根不能取最多关键字，而要取下限；非根结点也要取下限。

`DS_2014_004` 反过来问含关键字结点数最多。此时要让每个结点中的关键字尽量少，但不能把 B 树想成单链，因为 B 树仍要求所有叶结点同层。

`DS_2021_002` 进一步暴露了“关键字数”和“结点数”混淆。B 树中 `[X X]` 是一个结点、两个关键字，不是两个结点。题目说某层有若干关键字时，先不要自动翻译成若干结点。

这一类题的固定入口是：

```text
先写 m 阶含义
再区分孩子数、关键字数、结点数、高度
最后看题目问最多还是最少
```

### 2. B 树插入：先落到底层，满了才分裂

`DS_2020_003` 暴露的是插入流程跳步。

B 树插入不是看到一个关键字就往根里塞，而是：

```text
从根开始查找
→ 找到最底层应插入的结点
→ 插入并保持结点内有序
→ 若关键字数不超过 m-1，结束
→ 若超过 m-1，分裂，中间关键字上移
```

今天要特别记住：

```text
只有分裂时，中间关键字才会上移。
普通插入不会直接跑到根结点同层。
```

另外，“借兄弟”是删除下溢时的处理，不是插入时的处理。插入是满了分裂；删除是少了借或合并。

### 3. B 树删除：删完必须检查下限

`DS_2012_005`、`DS_2022_001`、`DS_2023_004` 都在强化同一件事：B 树删除不能只把关键字删掉就结束。

删除后要检查：

```text
当前结点是否低于关键字下限？
兄弟结点能不能借？
借时是否经过父结点分隔关键字调整？
调整后的每个子结点是否仍满足 B 树定义？
```

`DS_2012_005` 的关键点是：兄弟够借时，不能直接把兄弟关键字搬过来。必须：

```text
兄弟相邻关键字上移到父结点
父结点分隔关键字下移到当前结点
```

这样才能同时维护数量下限和关键字区间顺序。

`DS_2022_001` 的关键点是：判断删除后的根关键字序列时，不能只看根序列是否有序，还要检查根关键字之间对应的非根子结点是否达到关键字下限。

`DS_2023_004` 的关键点是：B 树删除内部关键字最终要转化为删除最底层终端关键字结点中的关键字，所以终端关键字结点内容或结构一定会变化。看到“一定”不要机械排除，要先回到算法过程。

### 4. B 树查找 vs B+ 树查找

今天 `DS_2017_003` 和 `DS_2023_004` 合起来补上了 B/B+ 的边界。

B 树：

```text
关键字和记录可分布在各层
查找成功可以停在任意含关键字结点
```

B+ 树：

```text
非叶结点只作索引
全部记录在叶子层
叶子结点按关键字顺序链接
查找成功必须到叶子层
更适合数据库索引、文件索引、范围查询
```

今天的一个典型错误是把“B+ 树结点可以放在磁盘块中”误理解成“B+ 树用于操作系统磁盘空闲块管理”。正确区分是：

```text
数据库索引 / 文件索引 / 范围查询 → B+ 树
磁盘空闲块管理 → 位示图 / 空闲链表 / 成组链接法
```

## 四、今晚的统一防错清单

今天所有题可以压缩成几条操作规则：

```text
折半查找：
数组/顺序表 + 有序，二者缺一不可。
静态链表逻辑上仍是链表，不能 O(1) 取中点。

折半查找判定树：
不要看路径是否左右交替，先数左右子树规模是否符合统一取中。

BST：
路径可以左、右、左交替；关键是每个结点都落在祖先限制出的区间内。

中序遍历：
中序本身只是左-根-右；只有 BST 才推出升序。
若题干给中序降序，要转成左大、根中、右小。

AVL：
BF 是高度差，不是结点数差。
插入后只调整最小不平衡子树，不全局重建。

B 树：
先写 m 阶上下限，再判断关键字数、结点数、孩子数、高度。
插入：先到底层，满了分裂，中间上移。
删除：删完查下限，少了借，借不到合并。
查找：B 树可在内部结点成功，B+ 树必须到叶子层。

B+ 树：
核心是有序索引和范围查询，不是磁盘空闲块管理。
```

## 五、明天回滚复习时的优先顺序

第一优先级是 B 树/B+ 树，因为今天的错误密度最高，而且错误类型覆盖了性质、计算、插入、删除、查找和应用场景。

建议先按这个顺序回滚：

```text
DS_2013_002 / DS_2018_001：B 树高度与最少关键字数
DS_2014_004 / DS_2021_002：关键字数、结点数、含关键字结点数
DS_2020_003：B 树插入路径与分裂上移
DS_2012_005 / DS_2022_001 / DS_2023_004：B 树删除与结构合法性
DS_2017_003：B+ 树应用和 B/B+ 查找区别
```

第二优先级是 AVL：

```text
DS_2012_004：BF 是高度差
DS_2021_001：插入后找最小不平衡子树并旋转
DS_2015_003：中序降序与反向二叉排序关系
```

第三优先级是折半查找：

```text
DS_2024_002：静态链表不能直接二分
DS_2017_002：折半查找判定树看统一取中分割
```

今晚结束时最该留下的一句话是：

```text
树形查找题先确认结构类型，再确认该结构约束的是关键字区间、左右规模、高度差、关键字下限，还是查找终止位置。
```
