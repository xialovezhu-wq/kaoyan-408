## 三、需要重新学习的六个断点

### 1. 管道：内核安全不等于应用语义正确

- 为什么复盘：MQ-02 首答高置信，两个修复回合后仍重复同一层次混淆。
- 当时怎么错：把内核提供缓冲区、互斥访问、指定读取者和消息完整性混成一个保证；把并发写问题说成覆盖。
- 正确边界：内核保证管道结构和单次读写操作按规则执行，读取具有消费语义；应用层负责接收者分配、先后顺序和逻辑消息边界。管道满时写者阻塞，不覆盖未读数据；多个写者的风险主要是消息交织。
- 复做第一动作：先分别写“内核保证什么”和“业务协议保证什么”，再讨论是否需要互斥、顺序控制或消息路由。

### 2. CPI、IPS、IPC 与 MIPS

- 为什么复盘：MQ-10 首答完全空白，反馈后仍存在单位链断点。
- 当时怎么错：把 IPS 说成每周期指令数，把主频除以 CPI 的结果直接叫 MIPS。
- 正确边界：`CPI` 是每条指令所需周期数，`IPC` 是每周期指令数，`IPS` 是每秒指令数，`MIPS` 是每秒百万条指令。平均 CPI 应按指令比例加权；`IPS = 主频(Hz) / 平均 CPI`，`MIPS = IPS / 10^6 = 主频(MHz) / 平均 CPI`。
- 复做第一动作：先写四个缩写的单位，再写加权平均 CPI，最后沿 `Hz -> IPS -> MIPS` 做单位换算。

### 3. 五层封装链、PDU 与地址字段

- 为什么复盘：MQ-14 同时暴露模型层数、PDU 名称和地址字段三类基础空白。
- 当时怎么错：漏掉 OSI 表示层、混乱会话层与运输层顺序，并把三类地址全部归入网络层。
- 正确边界：408 常用五层模型为“应用、运输、网络、数据链路、物理”；OSI 七层额外在应用层下加入表示层和会话层。五层 PDU 链为“报文 -> TCP 报文段 / UDP 用户数据报 -> IP 数据报 -> 帧 -> 比特流”；端口号属于运输层，IP 地址属于网络层，MAC 地址属于数据链路层。
- 复做第一动作：先声明采用五层还是七层，再逐层写 PDU 和地址字段，避免跨模型拼接。

### 4. 固件、引导加载程序与内核的交权链

- 为什么复盘：MQ-11 能记位置但不能稳定识别每一步的执行主体和交权对象。
- 当时怎么错：认为 BIOS 直接找到操作系统，并由操作系统把控制权交给内核。
- 正确边界：CPU 从复位入口执行 ROM / Flash 中的固件；固件完成自检和初始化后，在启动设备中找到引导加载程序，将其装入主存并交权；引导加载程序再从磁盘找到内核，将内核装入主存并交权；随后内核初始化。
- 复做第一动作：每一步都问“当前谁在执行、下一步装入谁、控制权交给谁”。

### 5. 显式栈与递归调用栈

- 为什么复盘：MQ-03 的堆排序部分已经恢复，剩余断点集中在非递归快排的栈结构。
- 当时怎么错：知道显式栈保存区间左右下标，也知道不复制数组，但不能说出它替代的结构。
- 正确边界：非递归快排的显式栈保存待处理区间边界，替代递归函数形成的隐式调用栈；递归栈帧保存参数、局部状态和返回位置，不保存整份子数组。
- 复做第一动作：固定复述“显式栈存区间边界，替代递归调用栈，不复制数组”。

### 6. 局部提速与总体加速比

- 为什么复盘：MQ-09 已理解定义，但变式计算出现简单加法错误，最终修复未闭卷验证。
- 当时怎么错：首次不知道总体加速比，修复时虽会拆分受影响与不变部分，但新总时间加法出错。
- 正确边界：先把原总时间拆成受提速影响部分和不变部分；新受影响时间等于原耗时除以提速倍数；新总时间为两部分相加；总体加速比等于原总时间除以新总时间。
- 复做第一动作：先列两行时间账，再计算新总时间，最后单独验算加法后才求比值。
