> [!answer]- 派生自查口径（首答后展开）
> 核心机制：CPU 时钟信号、时钟周期与指令周期的边界；多周期 CPU 中“周期数可变”和“时钟周期长度固定”的区分
>
> 达标标准：
> - CO_UNK_035 知识点：CO01-11 CPU 时钟周期
> - CO_UNK_035 安全摘要：围绕 CPU 时钟信号相关说法进行判断，需要区分时钟信号、时钟周期、指令周期、触发边沿和最长组合逻辑延迟。
> - CO_UNK_035 关键参数核验：判断项涉及每个时钟信号是否对应新指令、状态元件边沿触发、时钟周期与主频互为倒数、时钟周期受最长组合逻辑路径约束。
> - CO_UNK_035 错误入口核验：历史归档未记录明确错因；高风险入口是把一个时钟节拍等同于一条完整指令，或混淆时钟周期和指令周期。
> - CO_UNK_035 第一动作核验：先画三层时间单位：时钟周期、机器周期、指令周期；再把每个判断项归入对应层级。
> - CO_UNK_035 机制边界：CPU 时钟信号、时钟周期与指令周期的边界
> - CO_UNK_036 知识点：CO05-13 多周期数据通路
> - CO_UNK_036 安全摘要：围绕多周期 CPU 的特点进行判断，重点是区分不同指令需要的周期数可以不同，和系统采用的基本时钟周期长度通常统一。
> - CO_UNK_036 关键参数核验：比较对象涉及单周期 CPU 与多周期 CPU；判断点包括不同指令执行阶段数量、每条指令所需周期数、时钟周期长度是否随指令任意变化。
> - CO_UNK_036 错误入口核验：历史错因记录显示曾把“每条指令占用的周期数可变”误扩展成“时钟周期长度也随指令变化”。
> - CO_UNK_036 第一动作核验：先分两列写“周期个数”和“单个时钟周期长度”，再分别判断多周期 CPU 对这两列的影响。
> - CO_UNK_036 机制边界：多周期 CPU 中“周期数可变”和“时钟周期长度固定”的区分
