## 二、核心思想

- 空间有限

## 三、典型错因

- FIFO 和 LRU 混淆
- LRU 命中后没有更新时间
- 淘汰时机判断错误
- 状态表维护不完整
- 缺页次数和置换次数混淆
- Cache 缺失率题只按元素个数统计，漏掉读写语句中对同一数组元素的多次访问
- 缺页后跳过置换算法，直接使用不存在页表项中的页框号

## 四、错题节点

### 1. 基础概念题

- OS_2024_001 / OS_UNK_059：页面置换算法对比，重点区分 FIFO 看进入时间、LRU 看最近访问时间、Clock 看访问位二次机会。

### 2. 典型计算题

- CO_2016_005：顺序数组读写访问的 Cache 缺失率计算，重点先数每个数组元素的读写访问次数，再结合每个 Cache 块容纳的元素数统计分母。
- OS_2019_005：LRU 页面置换访问序列模拟，重点先判是否有空闲页框；有空闲页框时缺页只调入，不统计为页面置换。
- CO_2012_006：二路组相联 Cache LRU 命中次数模拟，重点先确定组号映射口径，再在每个 Cache 组内独立更新 LRU 最近使用状态。

### 3. 易混对比题

- OS_2021_001：请求分页存在位为 0 后进入改进型 Clock 置换，和 LRU 对比时重点区分“最近访问时间”与“R/M 位扫描轮次”，并确认牺牲页框后再拼接地址。

### 4. 跨模块类比题

- CO_2013_001：磁盘调度算法与页面置换算法类别边界，作为“调度对象 vs 置换对象”的跨模块对照；正式 ID 暂保留历史映射，不按 DMA 题复盘。

## 六、复盘提醒

页面置换和 Cache 替换都属于“有限空间 + 替换规则 + 状态更新”，可作 R07 跨科目类比（OS 改进型 Clock ↔ CO Cache 替换算法，同属“淘汰规则 + 状态位维护”）。改进型 Clock 要看两类状态位：访问位 R 和修改位 M，牺牲页优先级 (0,0) → (0,1) → (1,0) → (1,1)，优先淘汰 R=0、M=0 的页（没访问也没改、代价最低）。注意三类状态位边界：存在位/有效位看“页在不在主存”（缺页判据，不参与置换扫描），R 看“近期是否访问”，M 看“是否写过、淘汰要不要写回”，三者不要混入同一轮扫描。请求分页地址变换遇 Present=0 时先缺页/置换，再用换入后的有效页框号拼接页内偏移。
