## 二、核心思想

- 网络可以抽象成图
- 无向图边数可以转化为总度数账本
- 保证、任意、必然类图题要先构造最大反例，再加 1
- DFS 遍历序列记录首次访问顺序，不等于一条连续路径
- 邻接矩阵形态可以直接给出有向边方向约束，例如下三角全 0 表示边只能从小编号指向大编号
- 拓扑排序只要求有向无环，不要求图连通，孤立点也要排入拓扑序列
- DAG 也可以表示表达式依赖，相同子表达式只建一次并被多个运算共享
- 最小生成树是在带权无向连通图中选边，目标是连通全部顶点且总边权最小
- Prim 是从点集向外扩张，Kruskal 是按边权排序后选不成环的边
- Kruskal 维护的是森林和连通分量，不是一棵已经长好的树；两个端点在同一连通分量则跳过，不同连通分量则加入并合并
- 单源最短路径关注从一个源点到各顶点的路径总代价；边权全为 1 时，BFS 按层扩展能得到边数最少路径，Prim/Kruskal 不保证
- AOV 网用顶点表示活动、边表示先后关系，服务于拓扑排序
- AOE 网用边表示活动、顶点表示事件、边权表示活动持续时间，服务于关键路径
- 关键路径看源点到汇点的最长带权路径，关键活动看时间余量是否为 0
- 多条关键路径并存时，缩短工期的活动集合必须覆盖所有关键路径
- 路由选择本质是路径选择
- 不同协议使用不同的路径信息和更新规则
- 网络最大吞吐量 = H1 到 H2 的端到端最小割：必经的入口/出口链路常是瓶颈；全图带宽最小的链路若可绕行则不构成瓶颈（最大流=最小割，与 DS 图论割一致）

## 三、典型错因

- 只数题干已经明说的顶点，忘记用总度数检查是否还需要其他顶点
- 把可能连通的 n-1 条边误当成必然连通的边数下界
- 把 DFS 序列中相邻顶点误判为必须有直接边，忽略回溯
- 把拓扑排序存在性误判成连通性或遍历可达性，看到孤立点就误以为无法拓扑排序
- 把表达式 DAG 误当成普通表达式树，重复画相同子表达式，漏掉共享结点
- 看见邻接矩阵下三角全 0 时，没有转化为“有向边只能从小编号到大编号”，漏判一定无环
- 把最小生成树和哈夫曼树混淆，只记住“贪心选小的”而没有区分图中选边和权值结点合并
- 把最小生成树的总代价唯一误扩展成树形唯一，忽略等权边会导致多棵最小生成树
- 把 Prim 算法从不同顶点开始的输出误认为一定相同，或把 Prim 与 Kruskal 的输出误认为总不相同
- 把 Kruskal 的全局按边权排序误做成 Prim 的当前点集向外扩张，提前选了较大权边
- 把最小生成树误当成最短路径树，认为 Prim/Kruskal 也能保证源点到各点最短
- 把 AOV 网和 AOE 网混淆，忘记 AOE 网中边才是活动、顶点是事件
- 把关键路径误判为边数最多的路径，忽略关键路径看的是路径总权值最长
- 求事件最早发生时间时漏掉某个前驱活动，没有对所有前驱路径取最大值
- 把关键事件当成关键路径，或只找一条关键路径就判断缩短工期活动
- 多条关键路径并存时，误以为缩短一条关键路径上的活动一定能缩短总工期
- 最短路径算法过程不熟
- 路由和转发混淆
- 距离向量和链路状态混淆
- RIP、OSPF、BGP 的适用范围混淆
- 把全图带宽最小的链路当成端到端吞吐量瓶颈，忽略它非必经、可绕行（应找端到端最小割，而非全图最小边）

## 五、推荐复盘顺序

图的基本概念 → 有向图与无向图 → DAG 表达式依赖表示 → 邻接矩阵 → DFS 访问与回溯 → BFS 层次扩展 → 无向图度数和与边数关系 → 无向图边数上界 → 连通图定义 → 生成树 n-1 → 最大不连通图构造 → 必然连通边数界限 → 最小生成树 → Prim / Kruskal → 最短路径 → 拓扑排序 / AOV 网 → AOE 网 / 关键路径 → 路由算法

## 六、复盘提醒

先把图的基本概念、DFS 访问/回溯、BFS 层次扩展和边数界限判断稳住，再把路由问题抽象成图，对比最小生成树、关键路径、最短路径算法和路由协议的更新规则。最小生成树看到的是图中的边和整棵树总权值，单源最短路径看到的是从源点出发的一组路径；哈夫曼树看到的是一组带权叶子结点；AOE 网看到的是工程活动边和事件顶点，最长带权路径决定工期。MST 性质题里，总代价唯一不等于树形唯一；边权互异才是推出 MST 唯一的常见充分条件。
