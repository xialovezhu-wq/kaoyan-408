## 明早回滚顺序

### 1. MAR 位数：地址空间 vs 实际装机容量

优先级：最高。

今晚暴露：
- 曾把“主存地址空间”误看成“当前实际装机容量”。
- 需要稳住：MAR 位数看 CPU 需要表示的主存地址范围。

明早自测问法：
- 如果题目说“主存地址空间为 64MB，按字节编址，但实际只装了 32MB 主存”，MAR 至少多少位？看 64MB 还是 32MB？为什么？
- 如果题目只说“主存容量为 64MB，按字节编址”，MAR 位数怎么算？这个问法和“地址空间 64MB、实际装机 32MB”有什么区别？

自查口径：
- MAR 位数看可寻址地址范围。
- 明确给地址空间时，优先看地址空间；实际装机容量只说明当前有多少物理芯片响应。
- 只给主存容量时，通常把容量视作可寻址主存范围。

### 2. DRAM：完整地址信息位数 vs 外部地址引脚数

优先级：高。

今晚暴露：
- 计算能做对，但“完整地址信息位数”这个术语不熟。
- 需要稳住：完整地址信息位数回答能区分多少个单元；地址引脚数回答芯片外部实际需要几根地址线。

明早自测问法：
- 一个 `16M x 8 位` DRAM 芯片，完整地址信息位数是多少？外部地址引脚是多少？数据引脚是多少？三者分别由什么决定？
- 题目问“单片 DRAM 芯片引脚数”时，为什么不能先算整机需要多少片或片选线？

自查口径：
- 单片存储单元数决定完整地址信息位数。
- DRAM 行列地址复用后，外部地址引脚数按行/列分时复用口径计算。
- 数据引脚由芯片位宽决定。
- 片选线和整机片数属于整机扩展，不混入单片芯片引脚。

### 3. 主存扩展：bit/Byte 与地址段长度

优先级：中。

今晚暴露：
- 曾把 `4K x 8 位` 误说成 `32KB`。
- 后续小测已修正，但明早需要轻量保持。

明早自测问法：
- `4K x 8 位` 芯片组，在按字节编址系统中覆盖多少地址单元？地址段长度是多少？为什么不能说成 32KB？
- `2K x 8 位` 芯片组从 `0000H` 开始，地址范围到哪里结束？为什么最后一个地址要减 1？

自查口径：
- 按字节编址时，一个地址单元是 1B。
- 地址段长度看地址单元个数。
- 总 bit 数可以换算容量，但不能把 bit 直接当 Byte。
- 地址范围终点 = 起点 + 地址段长度 - 1。

### 4. Cache：index / tag / valid 与映射方式

优先级：中低。

今晚表现：
- `tag` 与 `valid bit` 已能分开。
- 仍需保持：index 在不同映射方式下定位对象不同，路数不等于组数。

明早自测问法：
- 32 行 Cache，4 路组相联，块大小 64B，物理地址 32 位：组数、index、offset、tag 分别是多少？访问一组时比较几个 tag？
- 直接映射、组相联、全相联中，index 分别定位什么？

自查口径：
- 组数 = Cache 行数 / 路数。
- 组相联 index 定位组；直接映射 index 定位行；全相联没有 index。
- tag 匹配目标块，valid bit 判断该行内容是否有效。

### 5. 磁盘访问时间与 RAID 分类

优先级：低，保持即可。

今晚表现：
- 平均访问时间拆分、转速到旋转延迟、扇区传输时间、RAID 分类已通过。

明早自测问法：
- 磁盘随机访问一个扇区的平均时间拆成哪几段？控制器延迟什么时候加？
- 给转速和每磁道扇区数时，如何得到平均旋转延迟和单扇区传输时间？
- RAID 中镜像、奇偶校验、条带化、Cache 分别偏可靠性还是性能？

自查口径：
- 平均寻道时间 + 平均旋转延迟 + 传输时间；题设给控制器延迟才加。
- 单圈时间来自转速；平均旋转延迟通常取半圈。
- 单扇区传输时间可由单圈时间 / 每磁道扇区数得到。
- 镜像和奇偶校验偏可靠性；条带化和 Cache 偏性能。
