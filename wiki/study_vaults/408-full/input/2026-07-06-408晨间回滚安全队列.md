## Q1. 磁盘格式化三阶段

闭卷回答：

1. 低级格式化主要产生什么？
2. 分区主要产生什么？
3. 高级格式化主要产生什么？
4. 扇区号、校验信息、扇区头尾控制信息属于哪一步？

> [!answer]- 自查口径
> 低级格式化管物理扇区结构，写入扇区头、扇区尾、扇区号、校验等控制信息；分区管磁盘逻辑区域和分区信息；高级格式化管文件系统结构。控制信息归低级格式化。

## Q2. 磁盘格式化容量

闭卷回答：

- 为什么格式化容量通常小于非格式化容量？
- 这个问题为什么不能用“清空数据后容量变大/变小”的生活经验解释？

> [!answer]- 自查口径
> 格式化后磁盘空间中不仅有用户数据，还要保存地址、同步、校验、扇区头尾和文件系统管理信息。一部分物理空间被管理开销占用，所以格式化容量通常小于非格式化容量。

## Q3. Cache 总容量与行位数

闭卷回答：

1. 题目说 Cache 能存放若干字或若干字节数据时，这表示数据区容量还是 Cache 总容量？
2. Cache 行数怎么由数据区容量和块大小推出？
3. 每行除了数据位，至少还要考虑哪些附加位？

> [!answer]- 自查口径
> 先把题设容量当作数据区容量；行数 = 数据区容量 / 每行数据块大小；每行实际位数还要加 tag、valid bit，若采用写回法还要加 dirty bit 等控制位。

## Q4. Cache 组相联映射第一动作

闭卷回答：

1. 为什么不能直接拿主存单元地址对 Cache 组数取模？
2. 第一动作先求什么？
3. 块内偏移在这里负责什么？
4. 最后用什么对组数取模？

> [!answer]- 自查口径
> 主存单元地址只是主存块内的具体位置。应先由主存单元地址和块大小求主存块号，块内偏移只定位块内位置，不参与选组；最后用主存块号对 Cache 组数取模。

## Q5. TLB / Page / Cache 三层关系

闭卷回答：

1. TLB 命中，命中的是什么？
2. Page 命中，命中的是什么？
3. Cache 命中，命中的是什么？
4. 为什么 TLB 命中和 Cache 命中都能推出 Page 命中，但 Page 命中不能推出 TLB 或 Cache 一定命中？

> [!answer]- 自查口径
> TLB 命中是页表项副本在快表中；Page 命中是所需页面在主存中；Cache 命中是目标主存块副本在 Cache 中。TLB 命中说明能直接得到在主存中的页框映射，Cache 命中说明主存块副本已在 Cache，因此页面必在主存；但页面在主存，不代表页表项副本一定在 TLB，也不代表目标主存块副本一定在 Cache。

## Q6. TLB 未命中但页表项有效

闭卷回答：

1. 这种情况发生缺页吗？
2. 系统接下来从页表项中取的是什么？
3. 写入 TLB 的是一条什么映射？

> [!answer]- 自查口径
> 不发生缺页。系统从主存中的页表项读取页框号/页框地址信息，并把“虚页号 -> 页框号”的映射副本写入 TLB，之后继续形成物理地址访问数据。
