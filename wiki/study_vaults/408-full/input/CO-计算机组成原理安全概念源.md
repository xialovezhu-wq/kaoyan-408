## CO01-08 指令执行过程

- 来源页：`wiki/concepts/CO01-08_指令执行过程边界.md`
- 正式节点覆盖数：5

### 概念边界
指令执行过程要把取指、译码、取操作数、执行、写回和 PC 更新分层看。PC 通常指向下一条待取指令，但转移类指令会根据条件和目标地址改变后续取指路径。

### 常见误区
- 把顺序执行的 PC 自动更新和转移指令改写 PC 混在一起。
- 看到条件转移就默认一定改写为目标地址。
- 把 CPU 执行机器指令的流程和高级语言程序执行混在一起。
- 把时钟周期、主频、指令周期和执行时间关系跨题混用。
- 只背“取指-译码-执行”，不判断每一步的数据/地址来源。

### 关系迁移
- 易混概念：PC 更新规则；顺序执行 vs 条件转移；机器指令执行 vs 高级语言程序执行。
- 上下游知识链：存储程序 -> 按地址取指 -> 译码 -> 按寻址方式取操作数 -> 执行 -> PC 更新。

## CO02-20 IEEE 754

- 来源页：`wiki/concepts/CO02-20_IEEE754边界.md`
- 正式节点覆盖数：5

### 概念边界
IEEE 754 单精度字段通常按 S | E | F 拆。S 是符号位，E 是偏置阶码字段，F 是尾数字段；规格化数的实际有效数是 1.F，真实指数是 E-bias。E 全 0 和全 1 是特殊边界，不能按普通规格化数直接套。

### 常见误区
- 把尾数字段 F 直接当成完整尾数，忘记规格化隐藏位 1。
- 把 bias 公式记错，或把偏置阶码当补码/负权理解。
- 把十进制小数部分的二进制形式直接当成 IEEE 尾数字段。
- 混淆规格化数、非规格化数、最大有限数和特殊值。
- 把自定义浮点格式的补码阶码规则套到 IEEE 754。

### 关系迁移
- 同一核心考点：5 个节点共同覆盖 IEEE 754 字段拆分、偏置阶码、隐藏位和特殊边界。
- 同一题型模板：机器码到真值、真值到机器码、字段极值判断互为正反向模板。
- 易混对比：IEEE 754 偏置阶码 vs 自定义浮点补码阶码；规格化隐藏位 vs 非规格化无隐藏位。

## CO04-08 寻址方式

- 来源页：`wiki/concepts/CO04-08_寻址方式边界.md`
- 正式节点覆盖数：6

### 概念边界
寻址方式回答“操作数或目标地址怎样得到”。它不是单纯背名词，而是要把指令中给出的字段、寄存器内容、存储器内容和立即数之间的关系拆清。

基本判断顺序：

1. 先判断指令字段里给的是操作数本身、寄存器编号，还是地址相关信息。
2. 再判断是否需要访问寄存器、主存，或先取地址再取操作数。
3. 最后区分有效地址计算和取操作数动作。

### 常见误区
- 把立即数推广成“数据都直接在指令中给出”。
- 混淆操作数、地址码、有效地址和存储单元内容。
- 只看地址字段，不看寻址方式对地址字段的解释。
- 在位数、字节、字长和可寻址范围之间发生单位换算错误。
- 把“冯诺依曼按地址访问存储器”误简化为“指令中直接包含全部数据”。

### 关系迁移
- 上下游知识链：冯诺依曼存储程序 -> 指令格式 -> 地址码/寄存器字段 -> 寻址方式解释 -> 有效地址或操作数。
- 易混概念：立即数、地址码、有效地址、存储单元内容、寄存器内容必须分层判断。

## CO05-05 寄存器

- 来源页：`wiki/concepts/CO05-05_寄存器边界.md`
- 正式节点覆盖数：5

### 概念边界
寄存器题要先判断寄存器服务的对象。通用寄存器偏向数据通路和机器字长；PC 关注下一条取指地址或转移后的取指地址；PSW 关注处理机状态；MAR/MDR 与访存地址和数据传送有关。

### 常见误区
- 把 PC、PSW、MAR、通用寄存器作用混在一起。
- 把条件转移和无条件转移后的 PC 更新规则混淆。

## CO05-15 微程序控制器

- 来源页：`wiki/concepts/CO05-15_微程序控制器边界.md`
- 正式节点覆盖数：6

### 概念边界
微程序控制器用微指令序列产生控制信号。做题时要把机器指令、微程序、微指令、微命令和控制信号分清：

- 一条机器指令的执行通常对应一段微程序。
- 微程序由多条微指令组成。
- 微指令给出若干微命令或控制信号。
- 微地址形成决定下一条微指令从哪里取。
- 与硬布线控制器相比，微程序控制器易修改、结构规整，但速度通常较慢。

### 常见误区
- 混淆机器指令、微指令、微命令和控制信号。
- 把微程序控制器的取微指令过程与取机器指令过程混在一起。
- 对微指令格式、编码方式和微地址形成方式边界不清。
- 把硬布线控制器和微程序控制器的速度、灵活性特点记反。
- 在 CPU 执行专题链中只记流程，不拆控制信号来源。

### 关系迁移
- 易混对比：微程序控制器逐条取微指令形成控制信号，硬布线控制器用组合逻辑直接形成控制信号。
- 专题链线索：CPU 执行过程专题中，微程序控制器负责解释“控制信号从哪里来”。

## CO06-11 程序中断方式

- 来源页：`wiki/concepts/CO06-11_程序中断方式边界.md`
- 正式节点覆盖数：5

### 概念边界
程序中断方式强调 CPU 在指令执行边界检测外部中断请求，满足开中断和未屏蔽条件后进入中断响应，再转入中断处理。要区分中断请求、响应、处理、结束确认，也要区分中断和异常。
遇到“哪些事件或机制能提出中断/异常处理请求”的题，先回到 CO05-18 异常的事件来源分类，再判断是否进入程序中断方式相关流程；不要把普通硬件机制、内部异常源和外部中断请求混成一类。

### 常见误区
- 把“检测到中断请求”误解成指令执行中途立即打断。
- 把外设发起的中断请求和处理结束后的确认/结束信号混为一谈。
- 混淆异常和中断的来源：当前指令内部同步事件 vs 外部异步事件。
- 未先判断事件是否属于中断/异常源，就直接套中断响应流程。
- 把 PC/PSW 等控制现场和通用寄存器现场保存责任混在一起。
- 与 OS 层系统调用、缺页处理等入口机制交叉时跨层混淆。

### 关系迁移
- 同一核心考点：5 个主节点共同围绕 CO06-11 程序中断方式；CO_2023_004 作为异常/中断源相关命中参与检测。
- 易混概念：中断检测时机、中断请求 vs 中断结束、异常 vs 中断、PC/PSW vs 通用寄存器现场。
- 跨科目连接：与 OS 的系统调用、缺页异常、设备 I/O 有相似入口语义，但不能把跨科目弱关系当成强关系。

## CO06-18 DMA 方式

- 来源页：`wiki/concepts/CO06-18_DMA方式边界.md`
- 正式节点覆盖数：6

### 概念边界
DMA 方式用于主存和高速 I/O 设备之间进行批量数据传送，目标是减少 CPU 对逐字节或逐字传送的直接参与。CPU 通常负责初始化传送参数，DMA 控制器负责传送过程中的地址、计数、读写控制和总线请求，传送结束后再通过中断等方式通知 CPU。

需要分开的层次：

- 控制主体：CPU 初始化，DMA 控制器执行传送控制。
- 数据路径：设备/接口与主存之间直接交换，不经过 CPU 寄存器逐项搬运。
- 总线占用：DMA 需要获得总线使用权，可能与 CPU 访存竞争。
- 结束通知：传送完成后再让 CPU 处理收尾或异常，不等于 CPU 全程参与传送。
- 适用条件：高速或批量交换只是需求信号，还要看设备接口、DMA 控制器和系统总线支持。

### 常见误区
- 把“设备高速或数据量大”误当成“必然可发起 DMA 请求”。
- 把 DMA 方式和程序中断方式混在一起，分不清 CPU 逐次参与和 DMA 控制器成批控制。
- 把 DMA 请求响应误套成中断响应，忽略总线/存取周期或流水段边界与完整指令周期边界的差别。
- 对 DMA 传送过程中的地址、计数、状态更新顺序不稳。
- 在带宽、字节数、字长、总线周期等计算中发生单位换算错误。
- 把 OS 层 I/O 管理语义和 CO 层总线/控制器语义混为一谈。

### 关系迁移
- 同一核心考点：6 个节点均围绕 CO06-18 DMA 方式，适合按同一知识点簇复盘。
- 上下游知识链：DMA 方式 -> DMA 控制器 -> DMA 传送过程 -> 总线仲裁/周期占用 -> 传送结束中断。
- 易混对照：DMA 方式 vs 程序中断方式；DMA 响应边界 vs 中断响应边界；DMA 控制器 vs I/O 接口；CO 层总线传送 vs OS 层 I/O 软件管理。
- 相关命中：`CO_UNK_064` 同时命中 `CO05-22 指令流水线`，复做时需要先把流水段边界和完整指令周期边界分开。
- 计算风险：带宽、字节数、字长、总线周期、传送次数必须先统一单位，再做数量关系。
